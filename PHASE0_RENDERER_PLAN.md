# Phase 0: Static Architecture Site Renderer

## Goal

Every teammate can open a URL and see the current robot architecture, without
installing anything, without a login, and without anyone remembering to export
and share a file. The site regenerates automatically on every push to the robot
repository.

Explicitly **not** in scope: web-based editing, accounts, a server, a database,
or real-time collaboration. Authoring stays in the existing desktop app.

## Why this shape

The desktop app already separates concerns cleanly enough that this is an
additive feature, not a rewrite:

- `src/frc_arch_modeler/domain/model.py` is pure dataclasses with `from_dict`,
  no Qt import. The renderer loads the same `model.json`.
- `src/frc_arch_modeler/services/export_service.py` already proves that a
  deterministic, presentation-independent renderer over the model works.
- `SourceAnchor` carries `relative_path`, `start_line`, `end_line`. On a web
  page those become clickable links straight into the robot code on GitHub,
  which the desktop app cannot offer. This is the single biggest new capability
  Phase 0 delivers.
- `importers/java/scanner.py` is stdlib + tree-sitter over a filesystem tree.
  It runs in CI against the checked-out robot repo with no changes, so the
  published comparison view can always reflect the current code.

The output is plain static HTML with inline SVG, generated by Python. No npm, no
JS build step, no runtime dependency on a CDN.

## Prerequisites (verify before starting)

1. **This repository has no git remote.** Push `frc-architecture-modeler` to
   GitHub first; the robot repo's workflow installs the renderer from it.
2. **The sidecar must be committed in the robot repo.** Confirm
   `.frc-architecture/` is not gitignored there and that `model.json`,
   `layout.json`, and `bindings.json` are tracked. Add `draft.json` to the robot
   repo's `.gitignore` - it is recoverable scratch state and should not be
   versioned.
3. **GitHub Pages availability.** On GitHub Free, Pages only serves from public
   repositories. If the robot repo is private, either publish from a separate
   public `robot-architecture` repo, or fall back to uploading the site as a
   workflow artifact and linking it from the run summary. Decide this before
   Step 5.

## Design decisions

**Inline SVG, generated in Python - not Mermaid.**
Mermaid would auto-layout the graph and discard the block positions in
`layout.json`. Those positions are hand-arranged by whoever authored the model,
and that arrangement is most of what makes a dense architecture diagram
readable. Emitting SVG directly preserves them, keeps the page self-contained,
and keeps the output byte-deterministic.

**Layout fallback matches the desktop app.**
When `layout.json` has no entry for an element, use the same deterministic
placement the canvas uses (`architecture_scene.py:439`): column
`index * (BLOCK_WIDTH + HORIZONTAL_GAP)`, with `BLOCK_WIDTH = 210` and
`BLOCK_HEIGHT = 116`. A model that has never been arranged still renders
sanely, and a model that has been arranged looks like the desktop canvas.

**Deterministic output.**
Rendering the same inputs twice must produce byte-identical files. This makes
the CI diff meaningful, allows caching, and makes golden-file tests possible.
Sorting rules follow `ArchitectureExportService._sorted`: case-folded name,
then UUID as tiebreak.

**Design-only first, comparison second.**
Steps 1-5 ship a working site from `model.json` alone. Step 6 adds the code
scan. If the scan step is ever broken or slow, the site still builds.

## Preparatory refactors

These are small and should land before the renderer, in their own commits.

### P1. Extract the palette from Qt

`src/frc_arch_modeler/ui/theme.py` holds the Voltage color constants but
imports `PySide6`. The site generator must not import Qt.

- Create `src/frc_arch_modeler/presentation/palette.py` with `VOLTAGE_YELLOW`,
  `VOLTAGE_BLUE`, `NEAR_BLACK`, `PANEL_BLACK`, `OFF_WHITE`, `MUTED_TEXT`, plus
  the comparison-state colors currently inline in `architecture_scene.py`.
- Have `ui/theme.py` re-export from it so no UI code changes behavior.
- Add `tests/unit/test_palette.py` asserting the module imports with no Qt
  loaded - run a subprocess that imports it and asserts `"PySide6" not in
  sys.modules`.

### P2. Fix the mojibake in `export_service.py`

Two strings contain a corrupted em dash (UTF-8 bytes decoded as cp1252 at some
point): the `| _None_ |` relationship row, and the trigger bullet separator in
`_command_lines`. They are cosmetic in Markdown but will be visibly wrong on a
web page. Replace both with a plain ASCII hyphen for encoding-safety, and add a
test that no file under `src/` contains the byte sequence `\xc3\xa2\xe2\x82\xac`.

## Implementation steps

### Step 1 - Site package skeleton

Create `src/frc_arch_modeler/site/`:

```text
site/
  __init__.py
  loader.py      # read model.json / layout.json from a root, no Qt
  geometry.py    # block sizes, auto-layout fallback, edge routing math
  svg.py         # architecture and behavior diagram SVG emitters
  pages.py       # HTML page assembly
  assets.py      # the single inlined stylesheet
  cli.py         # argparse entry point
```

`loader.py` wraps `ProjectStore` and `LayoutStore` but must tolerate a missing
`layout.json` (it already returns `{}`, which is correct) and must surface a
corrupt `model.json` as a clear non-zero exit, reusing the existing `ValueError`
message from `ProjectStore.load`.

Add to `pyproject.toml`:

```toml
[project.scripts]
frc-arch-site = "frc_arch_modeler.site.cli:main"
```

Add no new dependencies. The renderer is stdlib-only.

### Step 2 - Architecture diagram SVG

`svg.py::render_architecture(project, layout, options) -> str`

Nodes:

- Subsystems, commands, devices, and triggers - one rounded rect each, 210x116,
  positioned from `layout.json` or the fallback.
- Title line uses `FieldValue.effective`. Second line is the description,
  truncated with an ellipsis at a fixed character budget, with a `<title>`
  child carrying the full text for hover.
- Respect `minimized: true` from `layout.json` by rendering the 42px-tall
  collapsed form, matching `ArchitectureBlock.set_minimized`.

Edges:

- Command to subsystem for each entry in `Command.requirement_ids`.
- Device to owning subsystem via `Device.owner_subsystem_id`.
- Trigger to command via `TriggerBinding.command_id`.
- Explicit `Relationship` edges, labeled with `relationship_type`.

Route as orthogonal polylines between the nearest edge midpoints of the two
boxes. Do not attempt crossing minimization; the hand layout already accounts
for it.

The SVG `viewBox` is computed from actual node extents plus padding, and the
element gets `width="100%"` with `preserveAspectRatio="xMidYMin meet"` so it
scales on a phone.

**Escaping is a correctness requirement, not a nicety.** Every name and
description is free user text flowing into markup. Route all of it through a
single `escape_text` helper (`html.escape(value, quote=True)`) and test it with
a model containing a script tag, an ampersand, quotes, and a newline in a name.

### Step 3 - Behavior diagram SVG

`svg.py::render_behavior(diagram, layout) -> str`

Shapes per `BEHAVIOR_STATE_KINDS`:

| kind | shape |
| --- | --- |
| `state` | rounded rect with the name |
| `start` | filled circle |
| `end` | filled circle inside a ring |
| `decision` | diamond |
| `synchronization` | thick bar |

Transitions are arrows labeled with `trigger_label`; an empty label renders no
text, which is correct per the docstring on `BehaviorTransition`. When
`command_id` is set, link the label to that command's anchor on the page.
Positions come from the behavior layout the same way, falling back to
`behavior_scene.py:337` (`column * (STATE_WIDTH + HORIZONTAL_GAP)`,
`row * ROW_GAP`).

Render one section per entry in `project.behavior_diagrams`.

### Step 4 - HTML page

Single page plus anchors. A team this size does not need routing, and one page
means Ctrl+F finds everything.

`index.html` sections:

1. **Header** - project name, generation timestamp, and the source commit SHA
   short-linked to GitHub.
2. **Architecture diagram** - the Step 2 SVG.
3. **Behavior** - the Step 3 SVGs.
4. **Subsystems** - per subsystem: description, device table (name, type,
   mode), anchor id `#subsystem-<uuid>`.
5. **Commands** - per command: description, requirements as in-page links to
   subsystems, trigger table, anchor id `#command-<uuid>`.
6. **Relationship matrix** - reuse the shape of
   `ArchitectureExportService.render`, as an HTML table.

**Source links.** Where an element has a `code_binding`, build the link as:

```text
{repo_url}/blob/{sha}/{anchor.relative_path}#L{anchor.start_line}-L{anchor.end_line}
```

`repo_url` and `sha` are CLI arguments supplied by the workflow from
`GITHUB_SERVER_URL`, `GITHUB_REPOSITORY`, and `GITHUB_SHA`. When they are
absent (local runs), omit the links rather than emitting broken ones.

Styling lives in `assets.py` as one inlined `<style>` block using the palette
from P1. Dark by default, to match the desktop app. Requirements: readable at
360px wide, diagrams inside an `overflow-x: auto` wrapper so the page body never
scrolls sideways, and a `@media print` rule so people can print the diagram for
a design review.

### Step 5 - CLI and first deploy

```text
frc-arch-site build --root . --out _site \
  [--repo-url URL] [--sha SHA] [--title "Team NNNN Robot Architecture"]
```

Exit codes: `0` success, `1` model missing or corrupt, `2` bad arguments. Print
the output path and element counts on success.

Workflow in the **robot** repository, `.github/workflows/architecture.yml`:

- Triggers: `push` to the default branch, plus `workflow_dispatch`.
- `actions/checkout@v4`, `actions/setup-python@v5` with 3.11.
- `pip install "frc-architecture-modeler @ git+https://github.com/<org>/frc-architecture-modeler@main"`
- Run the CLI with `--repo-url ${{ github.server_url }}/${{ github.repository }}`
  and `--sha ${{ github.sha }}`.
- `actions/upload-pages-artifact@v3` then `actions/deploy-pages@v4`, with
  `permissions: { pages: write, id-token: write }`.

Also add a workflow to **this** repo running the existing checks, since there is
no CI here today:

```text
QT_QPA_PLATFORM=offscreen python -m pytest --basetemp .pytest-tmp
python -m ruff check .
```

### Step 6 - Code comparison (stretch; ship Steps 1-5 first)

The workflow already has the robot source checked out, so:

- Run `JavaProjectScanner` over the checkout.
- Run `ReconciliationService.reconcile(project, scan)`.
- Add a **Design / Code** section listing matched, modified, design-only,
  code-only, and unresolved elements, styled per state with a text label as well
  as a color - the desktop app already treats color alone as insufficient, and
  the same applies here.
- Render imported hardware and trigger tables with source links, mirroring
  `_scan_lines` in the export service.
- Guard it behind `--scan <path>`. If the scan raises, log a warning and emit
  the design-only site rather than failing the build.

This is the step that makes the site say something the model file alone cannot:
where the design and the robot code have drifted apart, updated on every push.

## Testing

New file `tests/unit/test_site_export.py`, following existing conventions
(`pytest`, `--basetemp`, no Qt import in unit tests):

1. **Determinism** - render a fixture project twice, assert byte equality.
2. **Golden file** - a small committed fixture model and its expected HTML, so
   structural regressions are visible in review diffs.
3. **Escaping** - a project whose names contain a script tag, `&`, `"`, and a
   newline; assert no raw script tag appears in the output.
4. **Missing layout** - render with `layout.json` absent; assert every element
   still receives distinct coordinates.
5. **Minimized blocks** - a layout with `minimized: true` produces the short
   block height.
6. **Behavior pseudostates** - one diagram containing all five kinds in
   `BEHAVIOR_STATE_KINDS` renders five distinct shapes.
7. **Source links** - with and without `--repo-url`; assert correct
   `#L<start>-L<end>` construction, and that links are omitted when unset.
8. **Corrupt model** - CLI exits 1 with the `ProjectStore` error message.

Run with the isolated runtime:

```powershell
& .\.runtime-env\python.exe -m pytest --basetemp .pytest-tmp
& .\.runtime-env\python.exe -m ruff check .
```

## Definition of done

- A teammate with nothing installed opens a URL and sees the current
  architecture diagram, subsystem and command detail, and the behavior state
  machine.
- Pushing a change to the robot repo updates that page with no manual step.
- Clicking a bound element opens the exact lines of robot Java on GitHub.
- Re-running the build with unchanged inputs produces byte-identical output.
- The desktop app is unchanged in behavior and its tests still pass.

## What this deliberately leaves for later

The static site is not throwaway if the team later wants editing: it becomes the
public read-only view of the web app, and the SVG emitters and page layout carry
over. The pieces that would need to be built fresh at that point are the API,
the interactive canvas, auth, and the sync layer - none of which this phase
constrains.
